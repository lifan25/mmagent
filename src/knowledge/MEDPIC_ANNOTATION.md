# MedPIC 患者条件核查：开发标注协议

本轮只完成公开数据准备、20题输入盲标注与现有规则的适配可执行性检查；不新增模型，不据此报告临床准确率。它是新增药物核查的外部开发材料，不是原 BIBM 的复现实验，也不与 SSPNet 的患者合并。

## 来源与抽样

- 作者数据：[MedPIC-Bench](https://huggingface.co/datasets/TIM0927/MedPIC-Bench)，固定版本 `9ef6db4f13865b14fc2e6be3f94dcfaf3a0cf983`，CC BY 4.0。原始文件和逐题输出只存本地忽略目录；引用、版本、许可证及聚合结果可提交。
- [论文第3节](https://arxiv.org/html/2608.03028v1#S3)称467道模拟病例题来自核验后的来源规则，全部题目经专家复核。该说明是作者报告，不代表本组已完成专家复核或取得真实患者病例。
- 按原始 `question` 字符串的 UTF-8 SHA-256 升序、原始行序号升序定序，前20题为开发 pilot；不根据答案、匹配率或运行结果换题。原字符串不先改写、翻译或去空白；哈希与行序号一并记录。
- 重复题干共享哈希，因此这20题不保证代表总体。剩余题仅称“未用于本地调参”；公开数据缺少配对ID和逐题来源规则ID，确认来源/配对分组前不称独立封存测试，不计算配对一致率，也不把剩余题用于补别名、调规则或挑阈值。
- 原 DDI 清单的195条封存样本继续保持原状，与本轮无关。

## 一个派生任务及边界

任务是：**根据病例明确提供的患者信息，核查哪些候选药应避免、属禁忌或不适合该患者。** 本轮仅纳入明确的 `avoid`、`contraindication`、`inappropriate` 题型。先只看输入判题型，再谈能否执行；纯慎用/监测、剂量调整、最佳替代治疗及其他题型单列为范围外，保留在20题清单中，不悄悄删去。

`avoid`、`contraindication`、`inappropriate` 保留各自 action；纯 `caution` 不纳主任务，不能将监测/慎用升级为禁用。混合提问须依据原文审阅；无法分开所要求动作时标 `uncertain`，不得用关键词命中直接批准资格。作者正确选项仍是原题答案；即使题目合格，也不能把所有未选选项转换为“临床安全”。

选择题选项通常是备选药，不是共同处方。每个候选单独结合病例核查；只有病例明确记录当前并用，或某选项本身是组合时，才能构造并用关系。禁止把整组备选答案作为同一张处方交给药物对规则。

## 三层记录与最少字段

A维护本地模板和准备命令 [prepare_medpic.py](../data_evaluation/prepare_medpic.py)，C按本协议填写；不另建一套重复模板。以下字段是必须保留的信息，可用嵌套字段表达。

| 层次 | 必须保留的信息 |
|---|---|
| 原始题与来源 | 数据版本、文件摘要、原始行序号/题ID、题干哈希、开发用途；原 `patient_vignette`、`question`、`options` |
| 输入标注 | 审阅者、时间、状态；题型及资格理由；候选选项ID与原文；成分/剂型/剂量/途径及各自映射状态；患者事实、原文证据与时间；当前用药/候选/既往用药角色 |
| 评价侧标签 | 原 `answer` 及作者任务/分类标签；来源审计；未来新增人审结论、裁决者/理由/时间；系统输出单独保存 |

盲标注输入只提供原题文本和稳定ID，不含 `answer`、作者解释/风险分类、系统结果或其他审阅者结论。作者标签单独只读保存；后续揭盲评分不能回写成模型特征或输入标注。

模板的包级字段 `reviewer` 填实际审阅者，`reviewer_kind` 只能是 `human` 或 `ai_draft`；未开始时均可为空。每题 `review_status` 使用 `pending`、`draft`、`complete`。`complete` 仅表示该份转写和资格初审已完成，不表示临床结论正确、专家审核或双人一致。B/C目前均是20题空包；agent数据审计另存，不能替两人填写完成状态或冒充双审。

每题先填 `eligibility.decision`（`in_scope` / `out_of_scope` / `uncertain`）、`action` 和 `reason`。`candidates` 保留全部选项的 `option_id`，填写 `entity_type`、`drug_name`、`ingredient_rxcui`、`dose`、`route`、`formulation`、`mapping_status`，无法确定的值保留空；例如“以上均无”须标为非药物选项，不能硬映射为药物。`mapping_status` 使用 `unresolved`、`ingredient_only`、`product_verified` 或 `not_applicable`；尚未开始的 `pending` 记录可保持 `unreviewed`。`in_scope` 候选即使映射为 `unresolved`，仍可在如实完成转写后设 `review_status=complete`，不能为通过校验虚填编码；转写完成不等于临床核查完成。

`facts` 每项使用精确键名 `field`、`raw_value`、`raw_unit`、`value`、`unit`、`status`、`time`、`evidence`，分别记录事实名、原始值/单位、规范值/单位（若可无歧义转换）、事实状态、时间含义和证据；`complete` 且 `in_scope` 的记录须包含这些键，不能改用中文键名。`status` 使用下方四种枚举；`not_reported` 时 `raw_value` 和 `value` 必须为 JSON `null`，不能填 `false`、`0` 或字符串“未知”。

`facts` 与 `candidates` 均用嵌套 `evidence` 数组保存证据；每个证据对象为 `{field, quote, start, end}`。证据中的 `field` 是原文位置，与事实项的事实名不同，只能定位原 `patient_vignette`、`question` 或具体选项如 `options.A`；`quote` 是精确原文。`start`、`end` 用原字段的 Python Unicode 字符索引，左闭右开，必须满足 `原字段[start:end] == quote`；不能对翻译或清洗后文本定位。确实未报告的事实可保留空证据数组 `[]`，但不能由此构造否定。

- `explicit_positive`：原文明示存在；`explicit_negative`：原文明示不存在；`not_reported`：未交代；`conflicting`：原文矛盾或无法确定。病例没有提过敏、妊娠、疾病或并用药，不等于否定。
- eGFR、肌酐清除率和血清肌酐是不同指标；不得只因数值接近或单位看似相似互换。保留 `mL/min/1.73 m²` 与 `mL/min` 等原单位；无法可靠转换就记未知。
- 年龄/孕周/给药频次分别保留单位；既往事实不自动当当前事实，缺具体日期则记录原文相对时间。不得推断剂型、口服途径或精确 RxCUI，也不得用作者答案补药物身份。

## 结论定义

以下是未来逐条来源核查的标注语义，不能代替尚未完成的人类标注，也不是擅自增加生产接口状态。

| 结论 | 条件 |
|---|---|
| `flag` | 有出处的适用规则、药物身份和明确患者事实共同支持题目所问的提示；保留具体 action |
| `clear_within_rule` | 在该条规则的准确范围内，明确事实足以排除其触发条件；仅此规则不触发，不表示整体安全 |
| `unknown` | 必要事实、药物编码或来源不足、冲突或待裁决，无法得出前两种结论 |
| `out_of_scope` | 题型或候选超出本轮冻结任务/规则范围；记录原因，不能当阴性 |

原作者答案另记为“该题选中/未选中”；新增临床结论另列，初始为空且待人审。知识库没有条目、引擎没有警报、作者未选某选项，均不足以建立临床阴性。

## 二人独立标注与裁决

1. A生成固定20题输入及B/C空标注包，记录规则/映射版本；B与C分别领取，不展示系统结果、作者答案或对方标注。若实际只有一人，记录单人状态，另一份保持 `pending`。
2. B/C各自先标注题型和资格，再逐候选标注身份、角色、患者事实与证据区间；用冻结来源标适用性与 action，不因某题难答就新增生产规则。转写和资格初审完成的题填 `review_status=complete`，锁定各自版本；来源或医学结论仍可待核实。命令校验只检查结构及证据定位，不验证临床正确性。
3. A比较两份锁定记录，报告资格、事实和规则结论各自的一致数/共同完成分母，列出分歧。单人、自动和未完成记录不进入“双人一致率”。
4. A可据原文裁决转写、单位或字段定位问题。医学规则解释或临床结论分歧须由老师或具备相关临床/药学资格的审阅者裁决；未解决时保留 `unknown`，不能用多数AI回答替代专家结论。
5. 保留两份原标注、最终裁决及理由，随后才由评价侧读取作者答案。若质疑作者答案，记录单独的争议状态与依据，不静默修改原标签或为了匹配系统结果改答案。

## 来源重合、可执行性与后续评价

逐条来源审计记录 URL、章节、版本/日期及与生产规则的关系：`same_document`、`same_guideline_family`、`different_primary_source` 或 `unknown`。公开数据未提供逐题来源，不能从论文列出的来源库替每题猜出处；仓库不同不等于知识来源独立。同源题可用于规则遵循检查，但须报告重合，不能充当独立临床验证。

本轮实际汇总20题总数、各题型/资格数量、事实与药物可编码数量、现有规则可执行数量及缺口；每个比例写清分母。没有新增人类标注时，新增临床准确率保持未评价。规则或别名在开发题上改动须另记版本，不能覆盖旧基线，也不能查看剩余题来完善适配。

待任务转换和双审完成，才预先冻结原题答案集合精确匹配率、全资格题回答覆盖率及未知数。未知保留在主分母，可判定子集结果仅补充；未覆盖选项不能当 false，不能据此输出“以上均无”。20题开发结果不与论文全量成绩直接排名。正式独立评价还需先确认配对/来源规则分组，重新划分并冻结规则、映射与指标。

验收：A能重建相同20题；盲包无标签；每条事实能回查原文和单位；未完成双审、来源未知、范围外和不能执行的题均有明确记录；无新模型或标签驱动的规则增补。
