# BIBM 诊断最小实现：真实规则权重学习与精确推理

本入口把有来源的症状关联转为规则，用 DXY 训练规则权重，再用已告知、已询问的症状推断疾病。它是 **BIBM 思路的受限条件 MLN 实现**，尚不是原文完整复现，也不与用药核查混用。MLN 指马尔可夫逻辑网：用加权逻辑公式定义可能世界上的概率分布。

## 原文与当前范围

[BIBM 原文](https://hdzhangust.github.io/static/files/papers/2023%20BIBM%20Integrating%20Automated%20Knowledge%20Extraction.pdf) III-A/B/C 描述检索、知识总结、规则形式化与迭代改进，再用 Diaformer 询问后的真阳性症状进行 MLN 判别式训练和诊断。其工具包括 GPT-3.5/GPT-4、文本嵌入、Alchemy 和 MCMC。原文给出部分提示模板，但本轮在[作者论文页](https://hdzhangust.github.io/publications.html)及公开代码检索中仍未找到对应完整代码、实际规则库或全部运行参数。检查日期：2026-11-14。

当前机器 PATH 中未找到 Alchemy 的 `learnwts` / `infer`；本次没有安装或运行 Alchemy。使用现有 NumPy/SciPy，以一个明确受限的规则族进行精确计算，数学对应见下文。[Alchemy 官方教程](https://alchemy.cs.washington.edu/tutorial/5_1Text_Classification_Coll.html)也展示了“恰好一个类别”的硬约束；这不意味着本次已取得与作者配置相同的网络。

## 为什么这是一个受限 MLN

对患者 p 和症状 s，定义完全可观察的谓词 `ObservedPositive(s,p)`：本次输入是否**实际记录**了该症状的阳性回答。它不代表一个潜在的“患者真实具有症状”变量。没有记录阳性、明确阴性、以及未知，在这个阳性证据视图中都不触发该谓词；程序没有把未知写成临床阴性。

每条规则 r 为：

```text
ObservedPositive(s1,p) ∧ ... ∧ ObservedPositive(sm,p) ⇒ Diagnosis(dr,p)
```

添加五个 `Diagnosis(d,p)` 一元先验公式，以及“每位患者恰有一个候选疾病”的硬约束。DXY 本身为单疾病标签任务；多病共存不在该模型范围内。患者之间无连接，因此整体条件分布分解为每位患者的条件分布。

令 `a_r(x)` 为该规则的所有观察前件都成立的指示量；疾病世界为 y。规则的真公式数严格为：

\[
n_r(x,y)=1-a_r(x)+a_r(x)\mathbf 1[y=d_r].
\]

这包括前件不成立时，蕴含公式对所有疾病世界均为真的情况。先验公式的真值为 `1[y=d]`。因此：

\[
P(Y=y\mid x)=\frac{\exp\{b_y+\sum_r w_r n_r(x,y)\}}
{\sum_{d=1}^5\exp\{b_d+\sum_r w_r n_r(x,d)\}}.
\]

对所有世界相同的常量 `Σr wr(1−ar)` 抵消后，可化简为：

\[
P(Y=y\mid x)=\mathrm{softmax}_y\left(b_y+\sum_{r:d_r=y}w_ra_r(x)\right).
\]

这是该受限规则族的精确化简，不是先手写加分再取一个 MLN 名字。代码实际构造各世界的真公式数进行计算；测试另行枚举全部布尔疾病组合并剔除不满足硬约束的世界，对照概率相等。

所有先验和规则权重均从训练标签学习，可为正或负。最小化：

\[
\mathcal L(w,b)=-\frac1N\sum_i\log P(y_i\mid x_i)
+\frac{0.01}{2}(\|w\|_2^2+\|b\|_2^2).
\]

梯度是模型期望真公式数减观测标签世界中的真公式数，再加正则项。固定特征时这是带正则的凸目标。程序记录优化器是否收敛、迭代数、最终目标及最大梯度，并用有限差分检查梯度。`prior_only` 保留同样的疾病先验和优化器、移除全部外部规则，是无规则对照；不再添加含义相同的重复对照。

本实现对**观察谓词**采用完整事实视图，**不对潜在未知临床症状做概率边缘化**。若要恢复一般潜变量、跨疾病约束或更复杂公式，需要更换推理后端并重新验证；不能把当前精确性推广到那些场景。

## 数据与泄漏边界

- 固定原始 DXY 的 423/104 分割，复用既有 seed=8 的训练/验证索引：339/84/104；MLN 可以保留 339 条训练样本，包括没有症状、只能贡献疾病先验的记录。原 Diaformer 训练曾跳过其中 1 条全空症状记录。
- 显性视图只取 `explicit_symptoms` 中真阳性；问诊视图再加入 `inquiry_symptom` 明确列出、且模拟回答为阳性的症状。绝不加入其他隐含症状。未记录的回答保持未知。
- 测试 `target_disease` 与 Diaformer 的疾病预测不进入 MLN 特征或规则提取提示；真标签只用于最后计算指标。训练标签只用于权重学习。
- 复用 339 条训练病例上的冻结问诊器，是原训练样本上的问诊，不是交叉拟合。84 条验证和 104 条测试不用于本次选规则、正则强度或迭代次数。
- 作者旧问诊实现遇到显性症状全空、且有可用隐含症状时会借首个隐含症状启动。适配器不会加入这种未询问的启动症状。本轮进一步核对：训练/验证/测试各 1 条空显性记录的隐含症状也全空，因此三个分组实际触发该分支的病例均为 0。主结果仍保留完整 104 条；另报 103 条非空显性测试病例，仅用于检查完全无症状病例的影响，不是去除一条已发生泄漏的记录，不能用其替代主分母或选择更好结果。
- 预先固定显性/问诊后两个视图，每个都报告有规则与无规则对照。验证仅报告，不择优后再重跑测试。结果没有经过概率校准。

## 运行

在仓库根目录，用现有 `.venv`；无需安装新 Python 依赖或 CUDA。第一步要求已有本地 Qwen 服务监听 `127.0.0.1:18081`，服务启动由项目本地推理入口管理。禁止同时向同一单并发服务发两组科研任务。

```powershell
.\.venv\Scripts\python.exe -m unittest src.knowledge.tests.test_bibm_diagnosis -v

# 官方来源摘要 → 实际本地模型候选规则；每次完整运行5次请求，没有病例输入。
.\.venv\Scripts\python.exe -m src.knowledge.bibm_diagnosis extract --structured --output outputs/knowledge/bibm-dxy-rules-v2

# 仅补训练病例的问诊推理，读取原权重，不训练Diaformer。
.\.venv\Scripts\python.exe -m src.knowledge.bibm_diagnosis replay-training --output outputs/knowledge/bibm-dxy-training-inquiry-v1 --device cuda

# 在来源一致性核对完成后，用保留通过规则的版本训练；raw rules.json 不能直接启用。
.\.venv\Scripts\python.exe -m src.knowledge.bibm_diagnosis run --rules outputs/knowledge/bibm-dxy-rules-v2/rules.source-reviewed.json --training-queries outputs/knowledge/bibm-dxy-training-inquiry-v1/train-predictions.json --output outputs/knowledge/bibm-dxy-mln-v1
```

输出目录必须尚不存在；重跑使用新后缀，保留旧运行。程序校验规则词表、重复公式、来源与疾病一致性、训练记录与原划分一致性及权重摘要。上述路径的实际运行状态以本目录 BIBM 专用聚合报告为准，命令本身不证明已运行。

## 产物和下一步验收

- `bibm-dxy-rules-v1`：首轮 5 次真实响应，因前件过多、出现词表外症状而失败，未用于训练。
- `bibm-dxy-rules-v2`：同一提示和来源，仅加 JSON Schema 约束的 5 次真实响应；14 条候选、来源一致性核对后保留 12 条。保留原始响应/候选、`source-review.json` 和 `rules.source-reviewed.json`，没有重写任何候选公式。再次生成新候选后，仍需先对照来源核对再训练，不能复用旧核对结论。
- `bibm-dxy-training-inquiry-v1`：339 条训练问诊记录、原检查点摘要、零更新次数与计时。
- `bibm-dxy-mln-v1`：协议、四组学习结果、疾病概率、触发规则及其权重、无标签的验证/测试 `.db`、训练 `.db`、便于核对的 `.mln` 和聚合 `summary.json`。
- `.mln` 使用 Alchemy 风格表达，未由 Alchemy 解析或执行；执行后端是 `mln.py`。测试输入 `.db` 不含任何 `Diagnosis` 事实。病例级文件和权重只留在 Git 忽略目录，仓库仅保存源码、公开来源摘要与聚合证据。

## 本次实际结果（2026-11-14）

首轮 5 次模型调用因格式不合格保留失败记录；第二轮只加解码结构约束，来源和提示未换，耗时 168.60 秒。14 条候选中，agent 拒绝“痒推断为揉鼻/揉眼”和“少饮水推断为口渴”两条来源外推，保留 12 条，未重写公式。来源选择/转述和一致性核对均由 agent 完成，**没有人类或临床专家审核**。旧来源快照误写 Human-selected/manual，现已更正当前文档与主体元数据；旧快照保留，五段源内容逐项一致，没有重跑选择更高成绩。

冻结 Diaformer 训练问诊推理用时 25.17 秒；原权重前后摘要相同，优化更新次数为 0。四组 MLN 固定对照共用时 0.21 秒，全部收敛。测试主分母始终为 104。

| 模型/证据视图 | 验证正确/84 | 测试正确/104 | 测试准确率 | 测试 macro-F1 |
|---|---:|---:|---:|---:|
| 无外部规则，仅训练疾病先验（两个视图相同） | 20 | 24 | 23.08% | 0.0750 |
| 显性阳性 + 12 条来源规则 | 41 | 41 | 39.42% | 0.3882 |

| 既有 Diaformer 对照 | 72 | 79 | 75.96% | 本表未重新计算 |

macro-F1 是先分别计算每种疾病的 F1，再等权平均，减少大类别对汇总的支配。完整混淆矩阵、负对数似然、优化收敛和逐规则覆盖统计见 [BIBM 聚合报告](reports/bibm-dxy-mln-20261114.json)。非空显性测试子集为 103 条，问诊后规则模型为 46/103（44.66%）；只作敏感性结果。

当前规则覆盖不足：问诊后训练集 204/339 例、测试集 54/104 例触发至少一条规则；一个规则在训练集从未触发。过敏性鼻炎仅剩一条来源支持的规则，其前件与普通感冒规则相同，缺少区分类别的知识；验证集已显示该类别 0/16 正确。更低测试成绩说明这个最小实现尚不能取代 Diaformer，不构成原文性能复现。没有因为这些测试结果补规则、改正则或追加提取轮次。

完成标准是这些环节真实连通、无未问症状泄漏、数学检查和模型重载一致，而不是达到某个测试准确率。下一阶段先独立审核提取规则的语义与疾病覆盖，再制定一次冻结协议的完整知识获取/迭代对照；不因本轮测试好坏反复补规则。本轮不能证明优于原文、临床有效性或研究创新性。
