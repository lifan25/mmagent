## 诊断分支：已经运行，尚未达到原方法效果

输入为 DXY 已告知、已询问得到的阳性症状；真标签只用于训练或评价，未询问隐藏症状不进入测试特征。agent 选择并转述5个官方来源，本地模型生成14条候选，来源一致性核对后保留12条，整条拒绝2条外推，未改写候选公式。来源核对由 **agent** 完成，没有人类或临床专家审核。

实际使用现有 NumPy/SciPy 的受限条件 MLN：观察阳性症状合取、单疾病硬约束、5个疾病世界精确归一化。权重从训练标签学习；不是假返回值，也不是 Alchemy/MCMC 原后端。完整知识检索、原文评分迭代和作者完整配置尚未恢复。

| 固定测试104条 | 正确数 | 准确率 |
|---|---:|---:|
| 仅疾病先验、无规则 | 24 | 23.08% |
| 显性阳性症状＋12条规则 | 41 | 39.42% |
| 问诊后阳性症状＋同12条规则 | 47 | 45.19% |
| 既有 Diaformer 基线 | 79 | 75.96% |

当前结果低于已有 Diaformer，不能称性能复现或方法提升。四组预设对照和完整104条分母均保留，未因测试表现补规则。详见 [诊断说明](BIBM_DIAGNOSIS.md) 与 [聚合JSON](reports/bibm-dxy-mln-20261114.json)。

## 用药分支：自动规则已接入，具体药物身份仍缺失

标签来源先由 agent 核对并转述，药物范围、编码和谓词预先固定；本地模型实际生成 statement 与 condition，原始响应、自评分和有限改写均保留。这是 BIBM 知识形式化思路的用药适配，没有声称自动实现网页检索/摘要，也不等于原诊断复现。

- [自动包](rules/medication-llm-reviewed-v2.json)：二甲双胍、布洛芬2条通过 agent 来源/逻辑核对；华法林条件树错误表达例外，整条拒绝，原始条件未用参照替换。
- [来源核对参照](rules/medication-reference-v1.json)：3条由 agent 编写的参照，与自动输出分开。
- draft / rejected 不执行。缺事实保留未知，未覆盖不写成安全；只标记，不删除或补充候选，不借当前真实处方补成分。

A 的 agent 默认显式加载自动包，C 单独调用 check() 的默认包仍是来源核对参照。两种运行使用完全相同的推荐候选和分数：

| 固定输入与默认自动包 | 本次计数 |
|---|---:|
| 原始输入 | 351 |
| 严格推荐接口支持 | 344 |
| 不支持编码而拒绝 | 7 |
| 支持的344条中：核查信息不足 | 127 |
| 支持的344条中：未覆盖／未检查 | 217 |
| 完整执行的成分规则判断 | 0 |

SSPNet 输出四字符 ATC3 类别，不能确定具体成分、途径和剂型，当前成分规则无法在这些实际候选上完整执行。自动包少检查的条目不是安全性改善。条件触发、不触发、缺失、例外和拒绝分支在明确虚构输入上检查，未混入实际病例指标。

## 使用与下一步

从仓库根目录可显式加载自动包：

    from src.knowledge.check import check, load_rules
    rules = load_rules("src/knowledge/rules/medication-llm-reviewed-v2.json")
    report = check(case, recommendation, rules)

诊断与药物提取命令分别见 [诊断说明](BIBM_DIAGNOSIS.md)、[核查说明](MEDICATION_CHECK.md)；完整 agent 命令见 [A的运行说明](../data_evaluation/RUNNING.md)。已有输出不得覆盖，不为了接手先重训 Diaformer/SSPNet。

先由 A 审核来源、原始生成与拒绝记录、分母及接口，再解决两个缺口：诊断侧的完整知识获取/迭代与规则覆盖；推荐侧有依据的具体药物输出和核查必要事实。更细药物输出须单独建立映射、训练和评价版本，不能把ATC3候选直接替换成目标处方。

旧测试已用于探索，正式确认需要未参与开发的新患者/独立队列；症状到用药串联还需同一批具备相应信息的病例。不在同一测试集反复调规则。零样本大模型清单/关系抽取/直接推荐实验延后；此前公开数据和轻量基线见 [辅助探索报告](reports/open-data-pilot-20261114.md)，其中环境准备阶段快照不代表当前模型状态。
