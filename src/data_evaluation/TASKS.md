## 第一阶段任务与交付顺序

### A1：病例组织与划分，优先交付给 B

- [ ] 为 MIMIC Demo、Synthea 分别读取并关联就诊、诊断、操作、药物。使用各自的编码体系，不拼接不同数据集患者。
- [ ] 按真实时间排序同一患者的就诊，去重当前集合，记录缺少诊断/操作/药物的就诊及筛选原因。Synthea 慢性病是否跨就诊延续需明确，不凭空补全。
- [ ] 统一导出原始编码病例：patient_id、visit_id、时间顺序、diagnoses、procedures、medications；药物是监督答案。B 在此基础上建立整数词表；预测适配必须把当前药物剥离。
- [ ] 固定 seed 和患者级 4:1:1 划分；同一患者的所有就诊只在一个集合。小样本不足时明确报告，不承诺任何预定有效样本数。
- [ ] 本地保存病例、划分清单和来源版本；Git 只提交代码及汇总人数、就诊数、缺失/排除数量，不提交真实 ID 和逐病例记录。

交给 B：本地导出路径、字段含义、划分读取方法、编码体系、筛选版本。交给 C：共享 Case 字段草案、未知值规则与明确虚构的联调样例。不要等 A2/A3 完成才交接 A1。

- [ ] 用可手算的小样例检查指标、患者不重叠、时间顺序、输入不含当前药物和未来记录。
