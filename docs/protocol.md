# 数据、模块接口与实验协议

版本：0.1-draft。推荐、规则核查与最小agent调用链已有实现和集成证据；协议仍待三人评审，不代表成员均已确认。运行入口见[A运行说明](../src/data_evaluation/RUNNING.md)。

A（@lifan25）维护本公共协议，B/C 在各自 TASKS.md 提交接口建议，由 A 汇总。各模块可以依据当前草案先编写独立实现和虚构样例检查；真实集成前，将未确定项解决并由 A 确认后冻结为 0.1。成员修改走 PR，由 A 审核合并；后续影响字段含义的修改需同步版本、示例和调用方，不能由某模块单方面改变共享字段。

## 1. 总体约定

第一版从已经确认的诊断和结构化病历开始。问诊诊断复现属于另一条任务，不能直接把其输出当成完整病历。

- 模块先使用 Python 函数和普通字典传递数据，JSON 文件用来展示或交换样例；JSON 是按字段存储数据的文本格式。本阶段不要求网络服务、数据库或特定 agent 框架。
- 每份消息带 contract_version、data_kind、case_id。data_kind 为 synthetic 或 restricted；仓库只提交 synthetic 的病例样例。
- case_id 在公开示例中必须为虚构编号。真实患者标识及病例级结果不得进入 Git。
- 一个历史记录对应一次就诊；history 按时间从早到晚排列，全部早于当前就诊。
- diagnoses/procedures/medications 在一次就诊内作为集合，先去重；不把排列次序作为临床含义。
- 编码必须带 system 和 code。模型输入再映射为该次数据/模型版本固定的整数词表。不同数据集、不同词表或不同药物编码层级不能直接混用。
- 模型没有支持的编码返回 unsupported_code，由调用方明确处理；不静默丢弃诊断、不猜测映射、不把所有未知药统一成同一种药。
- null 表示未知，[] 表示确实没有记录项。对于过敏等临床字段，[] 只能在数据来源明确记录“无”时表示已知无，不能用来替代未采集。
- 如模型允许空历史，history=[] 表示已确认无既往就诊，history=null 表示未取得历史。若模型不能支持，返回 needs_information 或 unsupported_input，不假装已支持。
- 当前实际用药答案放在评价数据中，与预测输入分离。

## 2. 病例输入 Case

| 字段 | 类型/含义 | 是否必需 |
|---|---|---|
| contract_version | 协议版本 | 是 |
| data_kind | synthetic / restricted | 是 |
| case_id | 当前病例编号 | 是 |
| diagnoses | 编码列表，当前已确认诊断 | 是；首版至少一项 |
| procedures | 编码列表；未取得时为 null，已确认无时为 [] | 是 |
| history | 历史就诊列表；未取得为 null | 是 |
| context | 扩展核查所需事实，如过敏、肾功能等 | 是；允许其中值未知 |

history 的每项含 visit_index、diagnoses、procedures、medications。visit_index 只表示时间先后，不使用公开样例中的真实就诊日期。

context 是否必需由实际采用的规则决定。SSPNet 原输入不包含某字段，不代表核查模块可以假设该字段已知。第一版不自行增加复杂临床数据采集功能；必要事实缺失时标为信息不足。

RxNorm v5的可选context快照仅提供同次就诊截止结束时的eGFR与阳性CABG记录，保留单位、时间、来源及冲突/缺失。该快照不进入SSPNet编码，不能被称作入院时已知事实；来源规则见[A运行说明](../src/data_evaluation/RUNNING.md)。

示例：[case.synthetic.json](../examples/case.synthetic.json)。

## 3. 推荐接口 Recommendation

入口：`src.recommendation.predict.recommend(case)`；批量调用用`SSPNetRecommender`实例复用已加载权重。`score_case(case)`另外返回本地评价全分数，避免重复推理，详见[B运行说明](../src/recommendation/RUNNING.md)。

| 字段 | 含义 |
|---|---|
| contract_version / data_kind / case_id | 与病例一致 |
| status | ok / needs_information / unsupported_input / error |
| input_issues | 缺失信息、未知编码或错误原因列表 |
| model_version | 可识别的代码版本、权重与词表版本；真实运行不得为空 |
| execution | model_inference 或 synthetic_fixture |
| candidates | drug: {system, code} 与 score 的列表 |

- score 在 [0,1]，是模型预测分数，不命名为“临床安全概率”。
- candidates 表示超过既定阈值的候选药物；阈值由训练/验证流程确定。评价模块所需的全词表分数应作为本地运行产物另行保留。
- status 非 ok 时，第一版停止向核查模块传递候选；先汇报原因。
- synthetic_fixture 表示人为编写的协议例子，不能计入指标或展示为模型预测。
- 输出顺序仅为展示顺序；药物集合一致不因顺序不同视为不同结果。
- 旧后端输出`ATC3`四字符类别；v5以独立训练权重输出原始`RxNorm`产品code，保留剂量/剂型等产品差异，不能混用两套词表。未知输入编码显式拒绝，不采用旧预处理中隐式UNK/丢药方式；严格接口覆盖率与既有离线模型指标分别报告。空操作可用，但`procedures=null`表示未取得，不能代替`[]`。
- v5真实目标在训练词表外时，仍保留为集合指标漏报，不作为未知输入拒绝理由。AP只在输入支持且目标全可表示的病例计算并报告分母，不伪造词表外分数。药物身份来自预测产品码的冻结公开元数据，不读取当前真实目标补身份。

示例：[recommendation.synthetic.json](../examples/recommendation.synthetic.json)。

## 4. 规则记录 Rule

每条候选规则至少记录下列信息，使用 [规则模板](templates/rule.md)：

| 字段 | 含义 |
|---|---|
| rule_id / version / kind | 唯一编号、版本、diagnosis 或 medication |
| statement | 自然语言规则与明确适用条件 |
| source | 标题、发布机构、URL/DOI、章节、版本/日期、检索日期 |
| evidence | 支持该规则的具体位置与简短摘录或准确转述 |
| required_fields | 需要哪些病例事实才能判断 |
| code_mapping | 涉及药物/疾病的编码及层级，映射来源 |
| action | 第一版默认 flag：标记供复核 |
| review_status | draft / reviewed / rejected |
| review_record | 提取与复核主体、日期、结论与限制；明确是agent还是人类 |

- 大模型自评分不能替代来源核查。
- reviewed 指组内来源、逻辑、编码和范围复核，不代表临床有效性已经确立。
- 本轮自动执行的来源/逻辑核对明确标agent review，未有同学或临床专家复核；不能把它写成人类专家审核。来源核对参照与实际模型形式化候选分开保存，只有经记录的来源/逻辑核对才启用候选。
- 没有医学专业审核条件时，记录这一限制；不要写成“专家确认”。
- 否定、可能性、条件、例外必须保留；不把“慎用”转换成“禁止”。
- diagnosis 规则不能直接支持某种药物推荐；medication 规则是新增扩展。
- draft/rejected 规则不进入正式核查；虚构规则仅能用于明确 synthetic 的测试。
- 第一版先标记问题，不自动删除候选。后续如调整集合，应保留原始候选、修改原因及对应对照实验。

## 5. 核查接口 CheckReport

入口：`src.knowledge.check.check(case, recommendation, rules=None)`；默认来源核对参照通过`load_rules()`加载。只处理相同case_id和兼容版本；每条规则另检查成分与范围，不把ATC3父类当作ATC5成分。指定RxNorm适配规则包时，从C的冻结产品表核对原产品的成分、途径与精确剂型，不信任候选自行添加的身份字段；未知产品保留缺元数据原因。自动生成的临床条件与agent核对的产品适用范围分别记录，未批准规则继续禁用。

| 字段 | 含义 |
|---|---|
| contract_version / data_kind / case_id | 与输入一致 |
| execution | rule_check 或 synthetic_fixture |
| status | checked / issues_found / insufficient_information / not_checked |
| applied_rules | 实际执行的 rule_id 和版本列表 |
| findings | 触发规则、涉及药物、匹配的已知事实和来源链接 |
| missing_fields | 哪些事实缺失，妨碍判断哪条规则 |
| unchecked_reasons | 没检查的原因，如未加载已复核规则、药物映射缺失 |
| coverage | 实际检查数量、待检查数量和范围说明 |

状态解释：

- checked：至少一条适用规则被完整执行，在已覆盖范围内没有发现冲突。
- issues_found：至少发现一个实际冲突；其他规则仍可能因缺信息没检查，必须保留相关字段。
- insufficient_information：存在适用规则，但关键事实未知，不能完成判断；也须报告已经执行的检查。
- not_checked：没有实际执行适用检查，不能显示为“未发现风险”。

存在冲突时 status 优先为 issues_found；否则有未知事实妨碍适用规则判断时为 insufficient_information；否则有至少一条完整检查时为 checked；其余为 not_checked。checked 仍须展示 coverage 和 unchecked_reasons，不能写成“已证明安全”。

同一药物不在规则覆盖范围内时，明确记为未覆盖；没有触发规则不等于没有风险。

本轮可执行规则增加`selector`（准确编码、途径、剂型）、`possible_atc3`（仅提示可能需要补身份）、`condition`（all/any/not与布尔或数值比较）。不靠当前处方答案补身份。缺失项为含rule_id、candidate_index、fields与reason的对象；coverage中checked_rule_count/pending_rule_count按候选×规则计数，不能叫患者准确率。完整例外保留在condition，不能省略。

示例：[check.synthetic.json](../examples/check.synthetic.json) 故意展示 not_checked：用于防止界面把空规则库显示成“全部通过”。

## 6. agent 的最小职责

- 输入检查 → 调用推荐 → 调用核查 → 展示结果。
- 缺字段或编码不支持时返回原因；不补造病史。
- 分开呈现模型候选、知识检查结论和未知项。
- 任何解释中的药物、规则与来源都应能回到工具输出，不让语言模型编造来源。
- 第一版用确定的调用顺序即可；是否引入 agent 框架由后续真实需求决定。

已实现`MedicationAgent.run(case)`：输入检查→一次SSPNet调用→核查→next_action；推荐非ok则跳过核查，核查不得改原候选。调用轨迹保留model_version、执行状态和规则版本；不额外调用语言模型写解释。`run_with_scores`只为本地评价另返回全分数。规则核查的四种状态与agent调度状态分开说明，见A运行说明。

## 7. 实验协议

### 7.1 共同要求

- 分开记录原论文复现与新增扩展。
- 数据版本、上游 commit、预处理版本、运行设置、随机种子、模型选择和命令写进实验记录。
- 验证集用于选参数、阈值和模型，测试集用于固定方案后的评价。不在测试集反复调整规则、阈值和模型。
- 论文值、本次值和虚构值分栏，不把论文数字填入“本次结果”。
- 正式主结果建议多个随机种子并报告均值与波动；执行单次基线时如实报告，不把单次结果作为稳定性证据。

### 7.2 SSPNet

- 按患者划分，患者的各次就诊不得跨训练/验证/测试集。按论文 4:1:1 核查上游实现与实际记录顺序。
- 药物共现图从训练数据构建；若复现上游做法涉及全量统计，记录与防泄漏方案的差异，不静默掩盖。
- 词表、筛选与映射按确定的预处理协议固定；如依赖测试统计，明确其影响。
- 预测仅使用当前可用诊断/操作及早于当前就诊的历史，不输入当前真实药物或未来信息。
- 至少报告 Jaccard、F1、PRAUC、DDI rate、平均推荐药数，固定按就诊/患者的汇总方式，防止均值口径不同。
- 比较：简单基线、完整 SSPNet、去掉 PDRM。上游论文数值与本次同条件重跑值分开。

### 7.3 BIBM

- 从 DXY 或 Muzhi 的来源划分开始，验证集的处理方法查清后记录，不擅自用测试集选参。
- 训练标签可用于学习；测试的真实疾病不能作为诊断输入或提示词中的答案。
- 模拟问诊只提供当时已询问并得到回答的症状，不提前暴露全部隐含症状。
- 原方法主要使用确认的阳性症状作为 MLN 证据；若新增阴性症状或改变信息量，作为有记录的改动。
- 比较完整流程与去掉规则迭代，保持其他知识来源、问诊证据和数据划分一致。
- 保存允许存储的知识来源、提示词、模型版本、规则和生成日期；历史服务不能复用时记录替换和影响。

### 7.4 新增结合

- 同一批病例、同一份 SSPNet 输出，比较知识核查覆盖范围、冲突发现及误报。
- 若规则只标记而不修改候选集合，推荐准确率不会因标记本身改变；不要声称推荐指标提高。
- 后续若重排/删除/补充候选，才比较变化后的准确性、DDI 和推荐数量，保留原始结果。
- 缺乏独立审核标签时，不报告“临床核查准确率”；可以报告可追溯性、覆盖率和人工检查的案例结果及局限。
- 两篇分别在不同数据集跑通不等于症状到药物的整条链路已验证。串联评价需要同一批具备相应信息的病例，且区分预测诊断与真实诊断输入。

## 9. 开发交接文件约定（草案）

以下约定帮助三个人独立实现与交接。A1已生成两套病例和划分，B已完成Synthea训练适配；公共recommend/check和A的调用链已实现，三方正式冻结待确认。版本仍为0.1-draft，成员发现实际数据无法满足时在自己TASKS.md提议，由A修改本协议，不自行更改另一模块字段。

### 9.1 A 交给 B 的病例与划分

建议在本地 data/processed/data_evaluation/<数据集与版本>/ 保存以下文件；格式可在首次交接时由 A/B 确认：

| 计划文件 | 必须表达的内容 |
|---|---|
| visits.jsonl | 每条为一次就诊，含数据集、data_kind、patient_id、visit_id、时间/次序、原始编码 diagnoses/procedures/medications；诊断/操作/药物带 system 与 code |
| main_visits.jsonl | v2 单独的主任务候选：至少两次有效就诊患者的有效就诊，含集合归属；不通过删全量文件实现筛选 |
| split.json | train/validation/test 的患者归属；相同患者的全部就诊只在一个集合 |
| manifest.json | 数据来源与版本、源表、准备代码版本、筛选与去重规则、缺失处理、排序方法、种子、划分比例、各阶段人数/就诊数 |

JSONL 是一行一条 JSON 的文本格式。patient_id、日期、真实病例和具体划分清单只在本地保存；可提交的汇总报告不包含这些标识。

visits 是含监督药物答案的学习数据，不是直接传给 recommend 的 Case。构造预测 Case 时，当前 medications 单独转为标准答案，历史仅保留此前就诊；不能把整个训练记录原样传入模型或语言模型。

v2 全量 visits 保留单次/缺失病例，不表示每条都可用于模型；split 仅覆盖主任务候选患者。prediction_examples.jsonl 保留全部候选的标签隔离示例；main_prediction_examples.jsonl 仅取有已结束且含可用药物历史的预测样本。首条和重叠就诊未必可用，不能把候选就诊数等同于主任务预测样本数。后续无历史对照需保留当前患者归属，避免同一患者跨不同实验集合泄漏。三次就诊子集可单列对照，不是全量层硬筛选。

v3 主任务仅要求诊断与药物非空，允许没有源表操作记录的就诊。procedures=[] 配合 context.procedure_record_status=not_recorded 表示没有记录，不能推断没有发生操作；有记录为 recorded。未知/未取得操作来源仍应使用 null，而不是强行转为空集合。候选患者变化后本版本重新划分，跨版本效果比较需显式对齐同一患者划分，不能只因种子相同就视为同一测试集。

保留原始患者划分。B 映射筛选后报告各集合剩余患者/就诊及排除原因，不根据模型表现重新挑患者。训练/验证/测试的诊断、操作和药物未知编码分别统计；默认不从测试集补齐训练词表。

### 9.2 B 交给 A/C 的模型与药物信息

| 对象 | 必须表达的内容 |
|---|---|
| 模型输入 manifest | 引用 A 的数据/划分版本、映射版本及药物层级、模型词表标识、图节点顺序/维度、DDI 来源与筛选、未映射处理、样本排除统计 |
| 预测交接 | case_id、所属集合、与 med_voc 同顺序的全药物分数、标准答案对齐方式、固定阈值、模型/词表标识、未支持样本及原因 |
| 给 C 的编码说明 | 每个 system/code 的含义、成分/类别层级、允许的转换关系、不支持项及映射覆盖；不依赖浮点预测分数猜药名 |

### 10.1 无需申请数据的首批实验（推理前约定）

用户要求暂不依赖申请中数据，直接推进公开材料上的实验。本批固定一个本地开放权重模型Qwen3-4B-Instruct-2507，Q4_K_M量化；模型/量化提交、运行器版本和调用设置随实际运行记录。不改原SSPNet/Diaformer环境，不调用付费服务，不外传病例。温度0、seed20261114、单并发，提示词无已解答案例。模型历史预训练是否见过公开数据未知。

- DDI药物清单定位：250例中以原始行序和seed20261114无放回抽取55例，前50例pilot、后5例格式开发，剩195例保留。先冻结输入、提示词和药名匹配规则；模型只见药物槽位/剂量，不见DDI与Classification列。原名/标签拼写不一致导致参考无法对齐时单列，不按效果追加别名。报告全50例结果、可评分数、明确回答覆盖率、参考药对命中率、回答正确率与格式失败；不能评估阴性清单误报率。本批为探索性pilot，不再把这55例称最终保留集。
